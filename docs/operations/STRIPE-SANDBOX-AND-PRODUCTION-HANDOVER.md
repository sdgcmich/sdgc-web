# Stripe Sandbox & Production Handover Runbook

## 1. Overview & Architecture

The Saugatuck Douglas Garden Club (SDGC) website handles annual membership dues ($50.00 USD) via a secure, server-verified Stripe Checkout integration.

### Core Payment Design

- **Server-Controlled Pricing & Metadata**: All dues line items ($50.00 / 5000 cents USD) and event tickets ($20.00 / 2000 cents USD), currency, metadata (`payment_reference`, `order_reference`, `dues_year`, `ticket_quantity`), and success/cancel URLs are constructed strictly server-side in `src/features/payments/stripe-provider.ts` and `src/features/tickets/actions.ts`. The client browser cannot alter transaction amounts or currency.
- **Club Bylaws Compliance**: A successful dues payment marks the payment record as `confirmed`, but keeps the member application status as `pending`. Club officers (Admin/Treasurer) must manually review and approve the membership pursuant to SDGC bylaws. Advance ticket purchases are completely decoupled from membership privileges.
- **Automated PDF Ticket Passes & 501(c)(3) Receipts**:
  - **Official Event Ticket Pass**: Available instantly upon successful checkout at `/api/tickets/[orderReference]/pdf`, featuring a printable vector-styled ticket with perforated stub, unique order reference, check-in instructions, and total admissions count.
  - **Official 501(c)(3) Dues Receipt**: Available to confirmed members at `/api/payments/receipt/[paymentId]/pdf`, complete with organization EIN, dues year, payment method, audit reference, and charitable deduction notice.
- **Webhook Authenticity & Anti-Replay**: The webhook handler (`src/app/api/webhooks/stripe/route.ts`) verifies cryptographic HMAC-SHA256 signatures against the raw payload body. It enforces timestamp tolerance (default 300s) to defend against replay attacks and supports multi-signature rotation.
- **Idempotency**: Webhook events are tracked in `audit_events`. Reprocessed or duplicate deliveries are acknowledged safely (`200 OK`) without double-crediting or mutating finalized records.

## 2. Environment Variables & Secret Isolation

The integration uses three standard environment variables. Never prefix server keys with `NEXT_PUBLIC_`.

| Variable Name                        | Required Environment             | Description                                                                                                                                                                                  | Example Pattern (Do NOT commit real keys) |
| ------------------------------------ | -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `STRIPE_SECRET_KEY`                  | Development, Preview, Production | Stripe API Secret Key or Sandbox Restricted Key. In development & preview, MUST begin with `sk_test_`, `rkcs_test_`, or `rk_test_`. In production, MUST begin with `sk_live_` or `rk_live_`. | `sk_test_...` or `rkcs_test_...`          |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Development, Preview, Production | Stripe Publishable Key for client-side components if needed.                                                                                                                                 | `pk_test_...` or `pk_live_...`            |
| `STRIPE_WEBHOOK_SECRET`              | Development, Preview, Production | Webhook signing secret generated by Stripe for the registered endpoint.                                                                                                                      | `whsec_...`                               |
| `LOCAL_PAYMENTS_SIMULATION`          | Local Development Only           | When set to `true`, permits offline test bypass. Must be `false` (or omitted) in Preview and Production.                                                                                     | `false`                                   |

> [!CAUTION]
> **Safety Guard**: `src/features/payments/stripe-provider.ts` contains runtime safety checks that strictly reject any `sk_live_` or `rk_live_` keys in `development` or `test` modes to protect live accounts from accidental sandbox test runs.

## 4. Webhook Configuration

### Supported Event Types

The webhook endpoint at `/api/webhooks/stripe` processes the following Stripe events:

1. `checkout.session.completed`: Identifies the completed dues session, validates amount ($50.00) and currency (USD), records transaction reference, transitions payment to `confirmed`, and logs audit trail.
2. `payment_intent.payment_failed`: Identifies failed payment attempt, transitions payment record to `failed`, records decline reason, and logs audit event.
3. `charge.refunded`: Identifies refunded charge, updates payment status to `refunded`, and records audit trail.

## 5. Client Handover: Production Setup & Activation Runbook

The client's administrator will independently configure live production credentials directly in Stripe and Vercel. **No credentials need to be shared with the development team.**

### Step 1: Obtain Live Stripe API Keys

1. Sign in to the organization's Stripe Dashboard at [dashboard.stripe.com](https://dashboard.stripe.com).
2. Toggle the dashboard switch in the top banner from **Test mode** to **Live mode**.
3. Navigate to **Developers > API keys**.
4. Copy the **Publishable key** (`pk_live_...`).
5. Reveal and copy the **Secret key** (`sk_live_...`) or create a **Restricted key** with write permissions for `Checkout Sessions` and `Webhooks`.

### Step 2: Register Production Webhook in Stripe

1. In the Stripe Dashboard (Live mode), navigate to **Developers > Webhooks**.
2. Click **Add endpoint**.
3. Enter the Endpoint URL:
   ```text
   https://saugatuckdouglasgardenclub.org/api/webhooks/stripe
   ```
   _(Or the primary production custom domain configured in Vercel)._
4. Select the events to listen for:
   - `checkout.session.completed`
   - `payment_intent.payment_failed`
   - `charge.refunded`
5. Click **Add endpoint**.
6. Under the newly created endpoint, find the **Signing secret** section.
7. Click **Reveal** to copy the secret key (starts with `whsec_...`).

### Step 3: Configure Environment Variables in Vercel Production

1. Sign in to [vercel.com](https://vercel.com) and navigate to the `sdgc-web` project.
2. Go to **Settings > Environment Variables**.
3. Add the following variables targeted exclusively to **Production**:
   - `STRIPE_SECRET_KEY`: Set to `sk_live_...` (Production only)
   - `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`: Set to `pk_live_...` (Production only)
   - `STRIPE_WEBHOOK_SECRET`: Set to `whsec_...` (Production only)
   - `LOCAL_PAYMENTS_SIMULATION`: Ensure this is set to `false` or deleted in Production.
4. Verify that **Preview** and **Development** remain set to test keys (`sk_test_...` or `rkcs_test_...` / `pk_test_...` / `whsec_...`).

### Step 4: Controlled Production Smoke-Test Procedure

1. Trigger a deployment or redeploy the latest production commit in Vercel so the newly added environment variables take effect.
2. From the live website (`https://saugatuckdouglasgardenclub.org`), log into an authorized officer account or submit a test membership application with a real credit card.
3. Verify that the user is redirected to Stripe Checkout with the correct club branding, description ("SDGC Annual Membership Dues"), and amount ($50.00 USD).
4. Complete the transaction using a live credit card.
5. In Stripe Dashboard > **Payments**, confirm the $50.00 charge is received.
6. In Stripe Dashboard > **Webhooks**, confirm the `checkout.session.completed` event returned `200 OK`.
7. In the SDGC Admin Portal (`/admin/dues`), verify the payment shows as `confirmed`.
8. Immediately issue a full refund via the Stripe Dashboard for the test transaction to ensure the refund webhook triggers and transitions the payment to `refunded`.

## 6. Rollback & Troubleshooting Guidance

- **Stripe API Unavailable / Invalid Key**: The dues page gracefully catches Stripe API errors and displays a clear error alert to the member: _"Unable to initialize payment checkout. Please contact the club treasurer or try again later."_
- **Webhook Signature Failure (`400 Invalid signature`)**: Occurs if `STRIPE_WEBHOOK_SECRET` does not match the specific webhook endpoint secret created in Stripe. Verify that the secret displayed in Stripe Dashboard matches the Vercel Production environment variable without extra whitespace.
- **Rollback Option**: If the live payment flow needs to be temporarily paused for any reason, club officers can direct members to submit dues via physical check mailed to the club's postal address (fully supported in `/dues` and `/admin/dues`).
